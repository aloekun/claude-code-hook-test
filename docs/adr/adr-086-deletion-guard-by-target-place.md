# ADR-086: 削除系コマンドは、消す対象の場所で止める

## ステータス

採用 (2026-10-22)

> 削除系コマンドを、コマンドの種類ではなく **消す対象のパスがどこにあるか** で止める。
> 懸念は「意図せずプロジェクトの外のファイル・フォルダを消す」ことで、作業中に作った一時ファイルの削除は止めない。
> 判定できない対象は確認する (決定 7。無人の実行では確認できないので実行されず、[ADR-043](adr-043-security-gates-fail-closed.md) の fail-closed を保つ)。
> 削除の機能を持つコマンドは数えきれないので、確認なしで実行してよいコマンドを許可リストで持ち、リストに無いコマンドはユーザーに確認する (決定 5)。

## コンテキスト

hooks-pre-tool-validate の default preset は、`rm -rf` を正規表現で一律に止めていた。この方式には 3 つの穴があった。

- **パスを見ていない。** scratchpad の中の作業用フォルダを消す `rm -rf` も止める一方で、`-f` の付かない `rm -r` は通していた
- **PowerShell に効かない。** 2026-10-20 に PowerShell tool を hook に配線した ([ADR-028](adr-028-pnpm-create-pr-gate.md) § 追記、PR #582) ときに実測すると、`Remove-Item -Recurse -Force src` はどの preset にも当たらなかった (順位 581)
- **別名・省略形・入れ子を拾えない。** PowerShell は `ri` / `rm` / `del` / `rd` などの別名と、`-r` / `-rec` のようなパラメータの省略形を受け付ける。`pwsh -c "..."` や `cmd /c rd /s` で包むこともできる

ユーザーの要件は「抜け道を残さない」「プロジェクトの外を消されるのを防ぎたい」「作業中の一時ファイルは消してよい」の 3 つで、これを満たすには、コマンドの種類ではなく対象の場所で分ける必要がある。

## 決定

1. **削除の対象を 1 つずつ、場所で分類して止めるかを決める。**

   | 場所 | 単一の削除 | 再帰の削除 |
   |---|---|---|
   | 一時ファイルの置き場 (このセッションの scratchpad、プロジェクト直下の `__*`) | 通す | 通す |
   | プロジェクトの中 | 通す | 止める |
   | このプロジェクトの Claude の memory ディレクトリ | 通す | 止める |
   | プロジェクトの外 | 止める | 止める |
   | 判定できない | 確認する (決定 7) | 確認する (決定 7) |

   プロジェクトの中の再帰削除を止めるのは、jj で戻せるのが追跡中のファイルだけで、未追跡や gitignore 対象 (`.claude/` の状態ファイルなど) は消えると戻せないため。memory の単一ファイルを通すのは、古くなった記憶を消すのが Claude の正規の作業であるため
2. **対象のコマンド**は、Bash の `rm` / `rmdir` / `unlink` / `find -delete` / `rimraf` / `git rm` / `git clean` / `git worktree remove` / `gh <noun> delete` と `gh api -X DELETE` と `gh extension remove` (GitHub 上のリソースは場所を判定できないので確認する) / `cargo clean` / `cargo uninstall` / `pnpm store prune` / `npm cache clean` / グローバルのアンインストール (`npm uninstall -g` / `pnpm remove -g`) / `mv` の移動元 (移動先が別の種類の場所なら、元の場所から消えるので再帰の削除として扱う) / awk の `system()` と sed の `e` コマンド、PowerShell の `Remove-Item` とその別名・パラメータの省略形・.NET の `[IO.Directory]::Delete` / `[IO.File]::Delete` / オブジェクトの `.Delete()`、cmd の `rd` / `rmdir` / `del` / `erase`、PowerShell の `Move-Item` と cmd の `move` の移動元。`sudo` / `env` / `nice` / `timeout` / `xargs` / `npx` などの前置きは、後ろのオプションを解析せずに、次に現れる削除・シェル・`cd`・前置きまで読み飛ばす (オプションの値をコマンド名と読み違えないため)。後ろのコマンドをそのまま実行する中継コマンド (`flock` / `busybox` / `wsl` / `watch` など) は名前の一覧では尽くせないので、知らないコマンドの引数に削除コマンドの名前が独立した語として現れたら、そこから先を削除として読む。語をデータとして扱うコマンド (`echo` / `grep` / `git` / `jj` など) の引数は中継として読まない (`git log --grep rm -- <path>` を削除と読まないため)。そのうち削除の subcommand を持つもの (`git rm` / `git clean`、awk / sed のシェルの実行) は、先に削除として読む。`bash -c` / `pwsh -c` / `cmd /c` で包まれた中身は、そのシェルの構文で読み直す (`eval` / `Invoke-Expression` / `trap` は読み直さずに確認する。決定 7)。同じコマンドの中で定義した別名 (`alias` / `Set-Alias`) は、呼び出しで展開して読む
3. **判定できない対象は確認する (決定 7)。** 外から来た変数 (`$HOME` / `$env:TEMP` など)、コマンド置換、パイプや `xargs` で渡された対象、行き先の分からない `cd` の後の相対パスが該当する。ただし、**同じコマンドの中で文字列を代入した変数**は展開して判定する (`S="<scratchpad>"; rm -rf "$S/x"` は通る)。前置きの代入 (`S=x rm -rf "$S/y"`) は記録しない — Bash では同じコマンドの引数は代入前の外側の値で展開されるため。`cd` / `Set-Location` で移動した先も追跡する。何を実行するか分からないもの、すなわち `pwsh -EncodedCommand`、中身にコマンド置換を含む `bash -c` / `pwsh -c` も確認する (外側のシェルが展開して埋め込むので、任意のコードが差し込まれうる)。PowerShell で文字列を作ってコードにするもの (`[scriptblock]::Create`、`$ExecutionContext.InvokeCommand`) も確認する。解決できないコマンド名 (`"$EXE" args`) は止めずに、決定 5 の確認に回す。PowerShell で変数・文字列・型・メンバー参照から始まる式 (`$env:PATH -split ';'`) は、コマンドではないので扱わない
4. **場所の基準は hook の入力から取る。** プロジェクトは `CLAUDE_PROJECT_DIR` (無ければ `cwd`)、scratchpad は `scratchpad_dir`、memory は `transcript_path` と同じディレクトリの `memory/`。パスは文字列だけで正規化し (`\` と `/`、Git Bash の `/c/`、`.` と `..`、`~`)、ファイルシステムは見ない
5. **確認なしで実行してよいコマンドを許可リストで持ち、リストに無いコマンドはユーザーに確認する (ask)。** 削除の機能を持つコマンドは `cargo clean` / `docker rm` / `npm cache clean` / `make clean` のように数えきれず、レビューのたびに新しいものが見つかった (PR #587 の pre-push review で 18 回)。リストに載せるコマンドだけ削除の機能を確かめて決定 2 で読めば、確かめる範囲は有限になる。リストに無いコマンド、知らない中継コマンド (`busybox` / `wsl`)、名前を解決できないコマンドは、実行前に PreToolUse の `permissionDecision: "ask"` で確認する (止めはしない。無人の実行では確認できないので実行されない)。実行されるコマンドは、前置き・別名・入れ子のシェル・コマンド置換の中まで集める。同じコマンドの中で定義した関数は確認しない (本体は定義の位置で読む)
   - **既定のリスト**は `src/hooks-pre-tool-validate/src/deletion_guard/allowlist.rs` が持つ (ファイルの閲覧・テキスト処理、このリポジトリの開発ツール、シェル、各シェルの組み込みと予約語、PowerShell の読み取り専用の動詞 `Get-*` など)。
   - **プロジェクトで足す**ときは `hooks-config.toml` の `[pre_tool_validate] allowed_commands` に書く (`*` で終われば前方一致)。足したコマンドの削除の機能は読まないので、削除の経路が無いことを確かめてから足す。
   - **リストに載せるとき**は、そのコマンドが削除できる経路 (subcommand・オプション・環境変数) を確かめ、決定 2 に足してから載せる
   - **確認 (ask) が出る経路は、抜け道とみなさない** (2026-10-23 ユーザー判断)。抜け道は、止めも確認もされずに削除が実行される経路だけを指す。未知のコマンドや珍しい構文をすべて読み分けるのは現実的でないので、判定できないものは確認に倒し、人が見て判断する。確認があまりに頻繁に出るコマンドは、後から許可リスト (`allowed_commands`) か止めるリストに登録して調整する。レビューで「確認が出るが、もっと細かく判定できる」という指摘は、抜け道の修正ではなく確認の頻度の調整として扱う
6. **旧 `rm -rf` の正規表現は削除し、この判定を default preset の一部として扱う。** default preset を外せば止まり、telemetry も `default` として記録する (発火件数の連続性を保つ。確認は `warn` として記録する)
7. **許可リストに載せたコマンドを読む深さに上限を置く (2026-10-24 ユーザー判断)。** 止めるのは、場所を判定できてプロジェクトの外 (または中の再帰) と分かる削除だけにする。それ以外は中身を読み分けずに確認する。
   - **コードを実行させる機能は、中身を読まずに確認する。** `eval` / `Invoke-Expression`、`trap` に渡すコード、`find -exec` / `-execdir` / `-ok`、sed の `e` コマンドと `s///e`、awk の `system()` とパイプでの起動、区切り語を引用しない heredoc の中のコマンド置換が該当する。`find -delete` は場所で判定する
   - **変数の値を追うのは、普通の代入 (`X=...`) と `cd` / `Set-Location` だけにする。** `for` / `read` / `printf -v` / `mapfile` / `unset` などで値を変えた変数は、値が分からないものとして扱う。nameref (`declare -n`) を宣言したら、どの変数を書き換えるか読めないので、以後はどの変数の値も追わない
   - **場所を判定できない削除は、止めずに確認する** (決定 1 の表)。確認は無人の実行では通らないので、ADR-043 の fail-closed は保たれる
   - **理由**: PR #587 では、CodeRabbit の 13 回のレビューと pre-push review で、これらの機能の中身を読み分ける経路の抜けが形を変えて繰り返し指摘された (sed の `e` は 2 回、nameref は 3 回、入れ子のシェルの状態の引き継ぎは 4 回)。読み分けを細かくするたびに次の抜けが見つかり、収束しなかった。中身を読まずに確認すれば、読み分けの抜けは生じない。過去のコマンド 5838 件を流すと、止まるのは 6 件 (以前は 8 件。判定できない 2 件が確認に移った)、確認は 332 件 (以前は 5759 件中 322 件) で、確認の増え方は小さい

## 帰結

### 利点

- scratchpad や `__*` の一時ファイルは、再帰でも消せるようになった (旧方式では止まっていた)
- `rm -r` と PowerShell の削除の抜け道が塞がった
- 過去の transcript の削除らしいコマンド 51 件を流すと、止まったのは方針どおりのもの (プロジェクトの外、`/tmp`、`target/` の再帰削除) と memory の削除 (決定 1 で通すことにした) だけで、変数の展開や `cd` の追跡で scratchpad の削除が正しく通ることも確かめた
- 許可リストを入れた後に、過去の Bash / PowerShell のコマンド 5041 件をすべて流した。止まったのは 8 件 (方針どおりの削除 6 件、中身の分からない `eval` と壊れた引用の 2 件)、確認が出たのは 53 件 (1.1%) だった。確認が出たのは、子プロセスで別のものを起動するコマンド (`claude` / `wsl` / `ollama` / `perl`)、プロセスやパッケージを操作するコマンド (`taskkill` / `winget`)、名前を解決できないコマンド、PowerShell の構文を誤って Bash に渡したコマンドで、どれも確認してよいものだった

### 欠点 / 留意点

- **見えない削除は止められない。** スクリプトファイルの中の削除 (`node x.js` の `fs.rmSync`、`python -c` の `shutil.rmtree`、`bash x.sh` や `-File` で渡した ps1) は、コマンド文字列に現れない。スクリプトの実行そのものを止めると日常の作業が成り立たないので、通している。ただし、コマンドの中にコードを書いて `node` / `python` に実行させるもの (`node -e` / `python -c` / `python - <<EOF`、スクリプトを指定せずにパイプや `<` で渡す形) は、中身を読めないので確認する (過去のコマンドで確認が 104 件から 186 件に増えた。全面的に確認する案は 507 件になるので採らなかった)。git がシェルに渡すコマンド文字列 (`git rebase --exec '…'`、`git submodule foreach '…'`、`!` で始まる alias) も読まない。コミットメッセージなどの文字列と区別できないため
- **上書きは確認に留める。** コピー (`cp` / `Copy-Item` / cmd の `copy`)、`ln -f`、`tee` (`-a` の追記を除く) / `Tee-Object`、`sed -i` と sed の `w`、`Set-Content`、`New-Item -Force`、出力ファイルを取るコマンド (`sort -o` / `uniq <in> <out>` / `split` / `xxd` / `iconv -o`)、上書きのリダイレクト (`> file` / `>| file`) の書き込み先は、既にあるファイルが置き換わって元の中身が消える (pre-push review と CodeRabbit の指摘)。書き込み先にファイルが既にあるかは文字列から分からず、新しいファイルを作るだけの書き込み (`cp x "$TEMP/x.bak"`) も多いので、プロジェクトの外や判定できない場所への書き込みは止めずに確認する。プロジェクトや scratchpad の中への書き込みは何もしない。追記 (`>>`)・ストリームの付け替え (`2>&1`)・捨てる先 (`/dev/null` / `nul` / `$null`) は対象にしない。リダイレクトを対象にしたのは 2026-10-24 のユーザー判断で、過去のコマンドでは確認が 177 件から 319 件に増えた (増えた分の多くは、一時ファイルを scratchpad に置く前の `> "$TEMP/…"` / `> /tmp/…`)。`curl` は削除の経路 (`-X DELETE`、FTP の `-Q "DELE …"`、`-o` の上書き) が多く確かめきれないので、許可リストに載せず確認する (PowerShell の書き込みは別の preset `powershell-destructive-write-block` が止める)
- **リストに載せたコマンドの設定ファイルは見ない。** `.cargo/config.toml` の `build.target-dir` で `cargo clean` の消す場所を差し替えられるが、コマンド文字列には現れない
- **シェルの完全なパーサではない。** 分からない構文は判定できない側に倒すので、珍しい書き方の正当な削除にも確認が出る。確認が頻繁に出るなら、パスを直書きするか、決定 5 の許可リストで調整する
- **プロジェクトの中の再帰削除は、ビルド成果物 (`target/` など) でも止まる。** 必要ならユーザーに依頼する
- `/tmp` は scratchpad ではないので止まる。一時ファイルは scratchpad に置く
