# ADR-087: 対応したレビュースレッドは、push の後に返信して閉じる

## ステータス

採用 (2026-10-24)

> レビュー (CodeRabbit) のスレッドを直したり棄却したりしたセッションが、そのスレッドを登録する。`pnpm push` は push の成功後に、登録したスレッドへ返信してから resolve する。
> 対応済みかを判断するのは登録する側で、仕組みは登録どおりに実行するだけにする。
> [ADR-023](adr-023-coderabbit-reject-thread-skill.md) の手作業 (棄却の返信と resolve) は、この仕組みで置き換える。

## コンテキスト

PR #587 では、CodeRabbit の 13 回のレビューで 49 件のスレッドが付いた。どれも修正した後に push したが、スレッドは返信も resolve もされないまま残った。push の手順に、スレッドを閉じる段が無かったためである。

- **収束が見えない。** pr-monitor は毎回「未解決スレッド 49 件」と報告した。新しい指摘があるのか、修正済みの残りなのかが、件数からは分からなかった
- **棄却も記録に残らない。** 範囲外として棄却する指摘は、理由をスレッドに書いて閉じるのが筋だが、ADR-023 は `gh api` を 2 回打つ手作業のままで、実際には行われていなかった

2026-10-24 に、修正済みのスレッドは修正が終わった時点で閉じるべきで、その手順は再 push の手順に組み込むべきだとユーザーが判断した。

## 決定

1. **対応済みかは、修正・棄却したセッションが登録して宣言する** (2026-10-24 ユーザー判断)。
   - 登録は `pnpm threads fixed <番号|URL> "<対応の要約>"` (修正) と `pnpm threads rejected <番号|URL> "<理由>"` (棄却)。番号は `pnpm threads list` の未解決スレッドの一覧のもの。取り消しは `pnpm threads forget`
   - 登録先は `.claude/review-threads-pending.json` (gitignore 対象、workspace ごと)。登録時に、リポジトリ・PR 番号・ブランチ・スレッドの ID を記録する
   - 返信と resolve が行われたかは `pnpm threads show` (閉じたものも含め、全スレッドの状態と返信) で確かめる。レビュアーが修正を認めたかは `--full` で返信の本文を見る。`gh api` を組み立てて確かめると、その都度許可の確認が出て作業が止まるため
   - `list` / `show` と登録 (`fixed` / `rejected` / `forget`) は、許可リスト (`.claude/settings.local.json.template` の `permissions.allow`) に載せて確認なしで実行する (2026-10-24 ユーザー判断: 確認のためのコマンドは専用のコマンドに置き換えて許可リストに登録する)。GitHub に書き込む `apply` は載せない (`pnpm push` の中で呼ぶ)
   - **採らなかった案**: push 後の takt が新しい diff と照合して判定する案は、LLM の判定をそのまま外部の PR に書き込むことになる。行が変わって outdated になったスレッドを閉じる案は、outdated でも未対応のことがあるので誤って閉じる
2. **修正済みと棄却の両方を閉じる。** 棄却は理由を返信してから閉じる。ADR-023 の手作業は、この仕組みで置き換える
3. **閉じる前に返信する。** 修正なら「`<push した commit>` で対応しました。<要約>」、棄却なら「対応しません。理由: <理由>」。後から経緯を追え、CodeRabbit も返信を学習に使う
4. **実行は `pnpm push` の push 成功後に自動で行う。** `pnpm push` の連結 (`cli-push-runner && cli-review-threads apply && cli-pr-monitor --monitor-only`) に入れる。push を承認した時点で、登録済みのスレッドを閉じることも承認したものとみなす (2026-10-24 ユーザー判断)
   - **失敗しても push を失敗扱いにしない。** `apply` は終了コード 0 で終わる。返信か resolve に失敗した登録は理由を付けて残し、次の `apply` で再試行する。返信だけ済んだ登録は、再試行で同じ返信を二度書かない
   - **書き込む先を取り違えない。** 登録時と PR 番号・リポジトリが違う登録は処理せずに残す。もう閉じているスレッドと、見つからないスレッドの登録は消す
5. **登録漏れは、push の後の案内で気づけるようにする。** 未解決で登録の無いスレッドが残っていれば、件数と登録のしかたを出す ([ADR-042](adr-042-rule-vs-mechanism-boundary.md): 登録を規約で求めるのでなく、漏れが見える仕組みにする)

## 帰結

### 利点

- 修正した push の後に、対応したスレッドが閉じる。未解決の件数が、まだ対応していない指摘の件数と一致する
- 棄却の理由がスレッドに残る

### 欠点 / 留意点

- **登録しなければ閉じない。** 登録は修正したセッションの作業として残る。漏れは決定 5 の案内で見えるが、強制はしない
- **派生プロジェクトでは有効にならない。** `pnpm push` の連結は各プロジェクトの package.json が持つので、CodeRabbit を使うプロジェクトが自分で連結に足す
- **夜間ループ・GitHub Actions の経路は対象外。** どちらも `pnpm push` を通らない ([ADR-052](adr-052-autonomy-execution-boundary-classes.md) の自律 actor が PR に書き込む範囲は広げない)
