# ADR-079: 起票由来タグ — 機構の効果を印象でなく数で測る

## ステータス

試験運用 (2026-09-03 導入)。**境界順位 500 以降の起票が 4 週分たまった時点で、退出基準の判定を初回実施し本 ADR へ追記する** ([ADR-039](adr-039-experimental-feature-standard-pattern.md) の bounded lifetime)。

## コンテキスト

[defect-convergence-plan.md](../defect-convergence-plan.md) は「不具合が出るたびに機構を足す」ループを回してきた。testability gate (機1) / open-questions gate (機2) / shell 判定の exe 移送 (機3) / 台帳残骸の検知層 (2026-09-02 の 5 本) はいずれも実測された不具合から生まれている。

**だが「機構を足したから減った」を確かめる手段が無い。** 同じ計画が退出条件として掲げているのは「defect 由来の起票が減っていること」だが、その判定を人の記憶で行うと**測るたびに答えが変わる**。減っていないなら機構は儀式であり、対象外に置いた網羅性強制 (G2 対策 = property-based test / 入力空間分割の table test 必須化) を再提案しなければならない。その分岐を印象で決めたくない。

### 分類が主観だと退出基準は自分で無効化できる

「defect 由来の起票が減った」は、**defect を improvement に付け替えるだけで作れてしまう**。測定軸を導入するだけでは足りず、分類の恣意性を落とす仕掛けが要る。

## 決定

**順位 table (`docs/todo-summary*.md`) の行に起票由来のマーカーを付け、決定論で数えられるようにする。**

| マーカー | 意味 |
|---|---|
| `[defect:G1]` | 不具合由来。**テストを書く場が無かった** (I/O 癒着 / shell 判定) |
| `[defect:G2]` | 不具合由来。**テストの場はあったが入力空間を覆っていなかった** |
| `[improvement]` | 不具合ではない改善 (機能追加 / 整理 / 予防) |

### 境界順位から先だけを対象にする

`ORIGIN_BOUNDARY_RANK = 500` (`src/lib-ledger/src/summary_gate.rs`) 以降の行にだけマーカーを必須とする。導入時点の最大採番が 499 だったため、**既存 261 行は一切触らない** (2026-09-02 ユーザー決定)。遡って分類し直すと、当時の判断を今の基準で塗り替えることになり、測定の出発点そのものが主観になる。

**値は下げてはならない。** 下げると既存行が一斉に違反になる。

### `[defect:*]` を名乗る条件を機械検査に落とす

詳細エントリ (`docs/todoN.md` の `### 順位 N:` ブロック) に**実観測の証拠**があることを要求する。証拠として認めるのは次の 3 形式だけである。

| 形式 | 例 |
|---|---|
| PR / issue 番号 | `#463` |
| GitHub Actions の run ID | `run 32589642740` |
| **宣言された**発火回数 | `発火: 4 回` |

**狭く取るのは fail-open を避けるため。** 「N 件」「N 回」のような一般的な数量表現まで認めると、ほぼ全文が証拠と判定されて検査が空洞化する。発火回数を宣言形 (`発火:`) に限るのも同じ理由で、数えたなら書けるはずであり、書かせることに意味がある。

**この検査は floor であって証明ではない。** 証拠らしき文字列があることしか見ておらず、それが本当に当該不具合の観測かは人間が読む。機械が保証するのは「**証拠を書かずに defect を名乗ることはできない**」までである。

証拠が無いものは `[improvement]` としてしか登録できない。これは [bugfix-batch-plan.md](../bugfix-batch-plan.md) の選定基準 (2)「実観測された不具合の修正」と同一の線引きである。

### G1 / G2 の別は人間が付け、迷ったら G1 に倒す

どちらとも言えない defect は **G1** とする。G1 は「テストを書く場が無かった」= 機構側の不足であり、機構の効果を**過大評価しない**向きに倒れる (fail-closed 側)。この判断は機械化しない — 「テストの場があったか」は設計の読解であって、regex や AST では表現できない ([ADR-042](adr-042-rule-vs-mechanism-boundary.md) Step 1)。

### fail-closed で拒否するもの

`cli-docs-lint` の `origin-markers` check が `pnpm lint:docs` (push の quality gate) で次を拒否する。

- 境界順位以降でマーカーが無い
- 未知のマーカー (`[defect:G3]` 等) — **欠落と同じ扱い**に倒す
- `[defect:*]` なのに詳細エントリに証拠が無い
- `[defect:*]` なのに詳細エントリを引けない (証拠の有無を確認できないため)

### 再分類は緩める向きだけ根拠を要求する

`[defect:*]` → `[improvement]` の変更は**退出基準を緩める向き**なので、変更行に `再分類根拠:` を書くことを必須とする。逆向き (`[improvement]` → `[defect:*]`) は根拠不要。

**この検査は履歴を要する**ため機4a には含めず、週次集計と同じ PR (機4b) で実装する — 変更の向きは「前の版と比べて」でしか判定できず、`jj file annotate` / diff を使う点が集計側と共通だからである。

## 検討した選択肢

### A. summary 行にマーカーを付ける (採用)

集計軸が**起票の場所そのもの**に乗るため、起票と同時に分類が決まる。順位という既存の一意キーで詳細エントリを引けるので、証拠の検査も同じ鍵で書ける。

### B. 別ファイルに分類台帳を作る (採用しない)

起票と分類が別操作になり、片方だけ行われる状態が生まれる。台帳の後始末漏れ ([ADR-072](adr-072-nightly-todo-loop.md) 決定 21) と同じ形の drift を新規に作ることになる。

### C. PR ラベルで分類する (採用しない)

起票 (todo) と実装 (PR) は 1:1 ではなく、起票されたまま実装されない行がある。**測りたいのは起票の流入**なので、実装側に軸を置くと母集団がずれる。

### D. 分類せず PR 数だけ数える (採用しない)

「機構を足したから defect が減った」と「単に活動量が減った」を区別できない。

## 帰結

- push の quality gate に検査が 1 つ増える (`pnpm lint:docs` の 5 つ目)
- **導入直後は空振りする** — 境界順位以降の行がまだ無いため。実データに 1 行足した対照実験で発火を確認済み (2026-09-03)
- 起票のたびに分類の判断が要る。判断そのものは 3 択で、証拠の有無は機械が指摘する
- 集計と退出基準の判定は機4b で実装する。**タグが溜まってからでないと集計の設計を実データで確かめられない**ため、順序を分けた
