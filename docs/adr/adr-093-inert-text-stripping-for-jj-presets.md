# ADR-093: jj 系 preset の判定の前に、実行されない `-m` の値と heredoc の本文を外す

## ステータス

採用 (2026-11-28)

> jj 系の preset (名前が `jj-` で始まるもの) は、`-m` / `--message` の引用された値と、区切り語を引用した heredoc の本文を外した文字列で照合する。外してよい受け手は許可リストで決め、外した後に字句解析器で元と同じコマンドかを確かめる。どちらかで疑わしければ外さず、元の文字列で判定する (ADR-043)。

## コンテキスト

`hooks-pre-tool-validate` の preset は、正規表現をコマンド全体に当てる。そのため、コミットメッセージや heredoc の本文に `--ignore-immutable` と書いただけ、本文の行頭に `jj new` と書いただけで、jj 系の preset がコマンドを止めていた。PR 本文やレビューの返信に jj のコマンド名を書くたびに止まるので、順位 620 (PR #667) で、判定の前に実行されない文字列を外すことにした。実装は `src/hooks-pre-tool-validate/src/inert_text.rs` にある。

着手前のヒアリング (2026-11-25) では、本文を実行しうる処理系を拒否リストで並べる形に決めていた。pre-push の fix step が、拒否リストに無い処理系 (`awk -f /dev/stdin`) で本文を外してしまう穴を見つけ (SEC-NEW-inert_text-L212)、許可リストに切り替えた。人間がレビューして採用したが、判断の記録はモジュールの doc にしかなかった。[ADR-068](adr-068-fix-step-authority-boundary.md) は設計級の変更を fix の裁量で決めないとしているので、判断をここに残す (#667 の post-merge feedback、順位 629)。

## 決定

### 1. 外す範囲

次の 2 つを外す。

- (a) `-m` / `--message` の引用された値 (`-m '...'` / `-m "..."` / `--message="..."`)
- (b) 区切り語を引用した heredoc (`<<'EOF'` / `<<"EOF"` / `<<\EOF`) と、PowerShell の単引用符の here-string (`@'` ... `'@`) の本文

実行される文字列は外さない。

- 二重引用符の値に `$(` か `` ` `` がある (コマンド置換で実行される)
- 区切り語を引用しない heredoc と `@"` here-string (本文が展開される)

退けた案: 引用符の中をすべて外す。引用符は argv を変えないので、`jj rebase "--ignore-immutable"` や `jj new "main"` を見逃す。`bash -c '...'` の中身も見えなくなる。

### 2. 対象の preset

jj 系 (名前が `jj-` で始まる preset) だけが外した文字列で照合する。git のブロックなど他の preset は元の文字列で照合する。同じ誤検知が続けば広げる。

preset 名は列挙しない。列挙すると preset 名の一覧 (`presets::KNOWN_PRESET_NAMES`) と二重に持つことになる ([ADR-081](adr-081-single-fact-dispersion.md))。jj 系の preset を足せば対象に入る。

### 3. 外してよい受け手は許可リストで決める

- heredoc の本文を外すのは、コマンド列のすべてのコマンドが `HEREDOC_READERS` (本文を読むだけと分かっている、コマンドとサブコマンドの組) にあり、語がすべて文字列として決まり、置換を含まないときだけ
- `-m` の値を外すのは、そのコマンドが `MESSAGE_TAKERS` (`jj describe` / `git commit` など) のときだけ

次の形は外さずに元の文字列で判定する。

- リストにない処理系 (`bash <<'EOF'`、`awk -f /dev/stdin`、`cat <<'EOF' | sh`)
- 変数で決まるコマンド (`$SHELL`)
- 許可リスト内のコマンド名の下で別のコマンドを起動する形 (`pnpm exec awk`、`git -c alias.x=!sh x`)
- プロセス置換で本文を流す形 (`tee >(bash)`)
- エディタや対話ツールを起動するオプション (`--edit`、`-i`、`--tool`) や、前置きの環境変数 (`JJ_EDITOR=...`) がある形

退けた案: 処理系を拒否リストで並べる。並べ漏れた処理系 (`awk` / `make`) が受け取ると本文を外してしまい、本物のコマンドを見逃す側に倒れる。許可リストなら、漏れても外さない (止まりすぎる) 側に倒れる (ADR-043)。

### 4. 大域オプションの位置

サブコマンドは、コマンド名の直後の語でなければならない。`git -c core.editor=bash commit` や `jj --config ... describe` のように前に大域オプションを置くと、許可リスト内のコマンドに別の処理系を起動させられるので、許可リスト外とする。`git -C dir commit` のような無害なものも、区別せずに外さない側に倒す。

jj は大域オプションをサブコマンドの**後ろ**でも受け付ける (2026-11-25 と 2026-11-28 に jj 0.42 で確認)。後ろの扱いは次のとおりとする (順位 629)。

- `--config` / `--config-file` (`--config=...` のように値をつなげた形も) は、後ろにあっても許可リスト外とする。設定でエディタやエイリアスを差し替えられる点は、前に書いた形と同じである。jj 0.42 は long option の前方一致 (`--conf`) を受け付けず、`--config-toml` も受け付けないが、判定は `--config` で始まる語をすべて外さない側に倒す。コマンドが jj かどうかも見ない。許可リストの他のコマンド (`git commit`、`gh pr create` など) で `--config` で始まる引数を使う形は普段の手順に無く、当たっても外さない側に倒れるだけなので、条件を足して判定を複雑にしない
- `-R` / `--repository`、`--ignore-working-copy`、`--at-operation` など、設定を書き換えない大域オプションは、後ろにあれば許す。別の repo を指すのは `cd dir && jj describe` と同じで、`-m` か `--stdin` があればエディタは起動しない。前に書いた形 (`jj -R x describe`) は上のとおり許可リスト外のままで、非対称は残る。前に置く書き方はこのリポジトリの手順に無いので、止まりすぎる側の非対称として受け入れる

### 5. 外した結果が元と同じコマンドかを確かめる

外す前後の文字列を、削除ガードの字句解析器 (`deletion_guard::lex_segments`) で語に分ける。`-m` の値と heredoc の本文の他に違いがあれば、外すのをやめて元の文字列で判定する。外す走査が引用符やコメントを読み違えても、本物のコマンドを隠す側には倒れない。

## 結果

### 受け入れた見逃し

本文をファイルに書いてから、後の別のコマンドで実行する形 (`cat > x.sh <<'EOF'` の後で `bash x.sh`)。実行するときにファイルの中身は見えない。Write ツールでファイルを書く形と同じく、この層では捕まえられない。同じコマンド列の中で許可リスト外のコマンドを呼べば、外さない。

### 解決しない誤検知

- `grep "git-only"` のように、`-m` 以外の引用符の中に語を書いた形
- 許可リスト外の受け手に渡した本文 (決定 3)。止まったら許可リストに足すかを検討する
- `-m '--config ...'` のように、メッセージの値が `--config` で始まるコマンド (決定 4 の判定に当たる)
