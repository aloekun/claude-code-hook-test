# ADR-081: 同一事実の分散を lint と手順で抑える — routing 列挙の集合比較 + 変更手順

## ステータス

採用 (2026-09-13)

> 1 つの事実 (設定値・routing ポインタ・閾値) が複数箇所に書かれたとき、片方だけが
> 古くなる事故を抑える。**機械で照合できる 1 種類は検査にし、残りは変更手順として残す**
> という線引きを [ADR-042](adr-042-rule-vs-mechanism-boundary.md) に従って固定する。

## コンテキスト

2026-08-13、PR [#395](https://github.com/aloekun/claude-code-hook-test/pull/395) /
[#396](https://github.com/aloekun/claude-code-hook-test/pull/396) の post-merge feedback で
同じ形の事故が独立に 2 件観測された。

1. `docs/todo.md` preamble の routing (どの todo ファイルが新規追加先か) を更新した一方、
   それを読む whole-tree review facet 側には `todo6.md` / `todo2-7.md` という**旧世代の固定値**が
   残り、レビューが古い送付先を案内した。
2. weekly reminder の閾値「7 日」が 4 箇所に分散し、うち 3 箇所が古い前提のままで
   週次レビューが誤検出した。

いずれも「同じ事実が 2 箇所以上にあり、片方だけ直した」形である。人間に同期の義務を
課す運用は、分散先が増えるほど破れる。

## 決定

### 1. routing 列挙は機械が照合する (`pnpm lint:docs` の `todo-routing`)

`docs/todo.md` preamble と facet instruction が語る「番号付き詳細ファイルの集合」を、
実在する `docs/todo<数字>.md` の集合と突き合わせる。実装と集合の作り方 (順位 table を
除く / 範囲表記を展開する / 退役宣言は参照ごとに効く) は
[`src/cli-docs-lint/src/todo_routing.rs`](../../src/cli-docs-lint/src/todo_routing.rs) の
module doc が持つ。**規約の中身は機構側にあり、本 ADR へ書き写さない** — 写せば片方だけが古くなる。

### 2. 機械化しない 3 項目は変更手順として守る

閾値・設定値の分散は対象が定まらず、検査を書けない (ADR-042 Step 1)。次を手順とする。

1. **変更前に反映先を数え上げる** — `grep` で当該の値・ポインタを含む全ファイルを洗い出し、
   PR 内に反映先を列挙する。**列挙を信じず grep を信じる**: 手書きの列挙は 2 回続けて
   漏れを出した (2026-09-12、ADR-050 の誤記と台帳 3 ファイルの脱落)。
2. **「暫定措置」と書いた記述は、恒久化した時点で必ず書き換える** — 条件付き記述を残したまま
   条件が消えると、レビュアーが毎回「未文書化の暫定措置」として誤検出する。
3. **反映先リストを ADR 側に残す** — 次に変更する人が数え上げからやり直さずに済む。
   ただし**リストは grep の代わりにならない**: 手書きの列挙は古くなるので、着手時に必ず
   grep で作り直し、リストは「見落としやすい場所」の当たりを付けるために使う。
4. **記述を撤去するときは、その記述を指す参照も同時に消す** — 節を消して参照を残すと、
   次に読む人が存在しない節を探す。撤去前に `grep` で `§ <節名>` を洗う。
   **除外パターンはパスだけに効かせる** (`--exclude-dir`)。`grep -v <パス片>` は行内容にも
   当たるため、そのパスを引用している参照行を丸ごと落として「0 件」に見せる — 本 ADR を
   作った PR 自身がこれで 4 件の残存参照を見落とした (2026-09-13)。

### 3. 全箇所を 1 つの PR で揃える

分散した事実を変えるときは、反映先すべてを同じ PR に入れる。片方だけ直すと、残った側が
「古い前提」を語り続け、後続のレビューを誤誘導する。

## 帰結

### 利点

- routing の分散は**同期が要らない形**になった。片方を直し忘れれば push で止まる。
- 残りの分散に対しては「数え上げ → 1 PR」という具体的な手順だけが残る。

### 欠点 / 留意点

- 検査は番号付き詳細ファイルの集合しか見ない。順位 table (`todo-summary*.md`) の分割 part や
  閾値の分散は依然として手順頼りである。**実害を観測したら検査を足す**のであって、
  観測なしに機械化を広げない (ADR-042 § 改訂 2026-09-12 決定 1)。
- 項目 3 は 2026-09-11 に本リポジトリ自身で踏んだ (PR [#492](https://github.com/aloekun/claude-code-hook-test/pull/492)
  で節末尾の注意書きを消し、それを指す台帳エントリが宙に浮いた)。
