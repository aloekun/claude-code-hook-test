#### 設計決定 (案)

- **検査 A** は集合演算 1 本で書ける: 表で auto lane の順位集合 と § 対象外 の順位集合 の積が空
- **検査 B** の入出力を明示する。**入力**: 台帳の「**対象ファイル**」で始まる列 (現行のヘッダは
  `対象ファイル (実パス)`) から宣言パスを抽出する — 抽出は `lib-ledger` の `parse_target_files`
  が既に持つ契約 (注釈の丸括弧は本体から外れる) に従う。**照合対象**: 「**内容**」欄の
  バッククォート識別子を、**各宣言パスが指すファイルの中身**に対して探す。
  **失敗条件**: 宣言パスのファイルが存在しない場合、または識別子がどの宣言先にも存在しない場合。
  2026-08-23 に書いた検査スクリプトが原型 (リポジトリ全ファイルを索引化し外部コマンドに
  依存しない形)
- **偽陽性の扱いを決めるのが設計の肝** — 順位 281 は識別子 current_dir が lint rule の
  **検出対象**であって成果物ではないため B の照合に引っかかる。そのまま `cargo test` に
  入れると赤くなり続ける。除外の表現方法 (注釈欄に置く / 専用マーカー / allowlist) を決める
- **検査自身に既知陽性の対照実験を持たせる** — 2026-08-23 の初版は ripgrep が
  node の execSync 経由で空を返し、ヒット 0 件を継続扱いで握り潰して
  **何も照合しないまま全行 OK と報告した**。fail-open な検査は「異常なし」と「検査していない」を
  区別しない ([ADR-043](adr/adr-043-security-gates-fail-closed.md))

- [ ] 検査 B の偽陽性除外の表現方法を決める (281 が通ることを条件にする)
