# 未解決の問い

実装中に浮上した**設計の問い**のうち、ユーザーの回答をまだ得ていないものだけを置く。
[cli-push-runner](../src/cli-push-runner/src/stages/open_questions_gate/mod.rs) の open-questions gate が
本ファイルを読み、エントリが 1 件でもあれば **push を止める** ([ADR-077](adr/adr-077-open-questions-gate.md))。

## 何のためにあるか

設計の穴を見つけたとき、答えを待たずに仮定を置いて実装を進めること自体は正しい。**問題は、その仮定が
確認されないまま push され、後から不具合として発覚すること**である。ここに書けば push が止まるので、
仮定のままリモートへ出ていかない。

## 書き方

エントリは `## Q-<連番>: <問い>` の見出しと、次の 2 行で構成する。

```markdown
## Q-1: この判定の比較対象は何か

関連: src/cli-pr-monitor/src/stages/monitor.rs
仮定: 助言層なので fail-open (判定不能なら警告を出さない)
```

- **`関連:` はファイルパスだけ**にする。行番号は実装中にずれる
- **`仮定:` は必須**。回答が来たときにどのコードを直すべきかが、仮定を書いていないと分からなくなる
- **選択肢は書かない**。二択に見えて三択のことがある (実例: 順位 490 の「fail-closed か fail-open か」の答えは、
  どちらでもない「判定不能」という第 3 の状態だった)

## 解消のしかた

ユーザーの回答を得たら、**回答の内容を然るべき場所** (ADR / 対象コードの doc コメント / 作業計画書) に書き、
**このファイルからエントリを削除する**。ここに回答を書き溜めない — 本ファイルは常に「未解決の問いだけ」を含む。
